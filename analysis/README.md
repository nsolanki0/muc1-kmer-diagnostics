# Analysis

This directory contains the downstream computational analyses performed on the simulated _MUC1_ sequencing data.

The analyses use the processed _MUC1_ reads generated by the [`../data_generation/`](../data_generation/) workflow. K-mer feature tables generated from these reads are used as input for the machine-learning analyses, while VNtyper2 is applied independently as a conventional analysis baseline.

## Analysis workflow

The downstream analysis workflow can be summarised as:

```text
                    Processed _MUC1_ reads
                              │
                 ┌────────────┴────────────┐
                 │                         │
                 ▼                         ▼
        K-mer feature tables            VNtyper2
                 │                       baseline
                 ▼                         │
        ┌────────┴────────┐                │
        │                 │                │
        ▼                 ▼                │
 Main ML pipelines   Targeted /            │
                     methodological        │
                     analyses              │
        │                 │                │
        └────────┬────────┘                │
                 └────────────┬───────────┘
                              ▼
                         Comparison
```

The machine-learning analyses investigate the ability of k-mer-based representations to support _MUC1_ classification across different data domains and experimental settings.

VNtyper2 provides a conventional, non-machine-learning baseline against which the k-mer-based approach can be compared.

## Directory structure

```text
analysis/
├── baseline/

```

### `pipelines/`

Contains the main machine-learning pipelines used in the project.

The pipelines investigate different approaches to model evaluation and generalisation, including:

- **Within-domain evaluation**
- **Domain transfer**
- **Domain adaptation**
- **Domain-adversarial learning**
- **Hashed k-mer representations**

The main pipeline implementations are:

- `within_domain.py` — within-domain evaluation.
- `domain_transfer.py` — domain-transfer experiments.
- `domain_adaptation_part1.py` and `domain_adaptation_part2.py` — domain-adaptation experiments.
- `dann.py` — domain-adversarial neural network analysis.
- `hashed_representation.py` — analysis using hashed k-mer representations.

These scripts represent the principal machine-learning analyses supporting the thesis.

### `targeted_analyses/`

Contains additional analyses designed to investigate specific questions or provide focused comparisons related to the main machine-learning experiments.

These include analyses using:

- principal component analysis (PCA);
- random forest models; and
- artificial mislabelling experiments.

The targeted analyses provide additional evaluation of model behaviour and specific aspects of domain generalisation.

### `methodological_analyses/`

Contains analyses investigating methodological properties of the simulated data and the k-mer-based modelling framework.

The directory is divided into:

#### `bimodality/`

Contains analyses investigating the effect of bimodality removal on domain-transfer performance.

#### `family_haplotype_overlap/`

Contains analyses investigating overlap between family/haplotype-related samples and its implications for model evaluation.

These analyses provide methodological context for interpreting the results of the main machine-learning experiments.

### `baseline/`

Contains the conventional analysis used as a baseline for comparison with the k-mer-based machine-learning approach.

The baseline uses **VNtyper2** for _MUC1_ analysis.

The workflow consists of:

- `run_vntyper2.sh` — runs the VNtyper2 analysis on the generated samples.
- `extract_variant_coverage.sh` — extracts and summarises variant-coverage information from the VNtyper2 results.

The VNtyper2 analysis is independent of the k-mer feature-generation and machine-learning workflows.

## Relationship to feature generation

The machine-learning analyses use k-mer feature tables generated from the processed _MUC1_ reads.

The feature-generation workflow is located in [`../feature_generation/`](../feature_generation/).

The general relationship between data generation, feature generation, and analysis is:

```text
Data generation
      │
      ▼
Processed _MUC1_ reads
      │
      ▼
Feature generation
      │
      ▼
K-mer feature tables
      │
      ▼
Machine-learning analyses
```

The VNtyper2 baseline uses the generated sequencing data independently and does not require the k-mer feature tables.

## Computational environment

The analyses were developed and executed in a Linux-based, SLURM-managed computing environment.

Python scripts implement the machine-learning and statistical analyses, while Bash scripts are used where required to execute analysis tools and manage computational jobs.

The software environments and external tool requirements are documented in [`../environment/README.md`](../environment/README.md).

Not all software used by the analyses is included in the Conda environment specifications. External tools may be installed separately and invoked directly by the workflow scripts.

## Reproducibility

The individual analysis scripts contain the commands, parameters, and configuration required for their respective analyses.

Before running an analysis, the required input data and computational environment should be prepared according to the workflow described in the relevant directory.

The general order is:

1. Generate the simulated sequencing data using [`../data_generation/`](../data_generation/).
2. Generate k-mer feature tables using [`../feature_generation/`](../feature_generation/).
3. Run the relevant machine-learning pipeline or targeted/methodological analysis.
4. Run the VNtyper2 baseline where required for comparison.
5. Compare the resulting analyses according to the experimental design described in the accompanying MSc thesis.

Generated feature tables, model outputs, and analysis results are not stored in the repository.

## Project context

The analyses in this directory provide the computational implementation of the experiments described in the MSc thesis.

The dissertation provides the detailed experimental design, methodological rationale, parameter choices, evaluation procedures, results, and interpretation of these analyses.
